# TrustPay 데모 발표 스크립트

## 0. 준비

배포 웹 데모를 기본으로 사용합니다.

```text
https://xrpl-tawny.vercel.app
Consumer 010-2000-0001 / OTP 123456
Business 010-1000-0002 / OTP 123456
PIN 123456
```

비상 시 로컬 fallback을 사용합니다.

```bash
pnpm demo:reset
pnpm demo:api
pnpm demo:mobile
```

## 1. 문제 제기

> 헬스장, 학원, 미용실처럼 장기 선불 결제가 많은 업종에서는 사업자가 폐업하거나 서비스를 중단했을 때 소비자가 미이용분을 돌려받기 어렵습니다. TrustPay는 전액을 바로 사업자에게 넘기지 않고, 선불금을 보호 원장에 나눠 잠그는 방식으로 이 문제를 해결합니다.

## 2. 소비자 보호 상태

Consumer `010-2000-0001`로 로그인합니다. 홈에서 `전체` 필터를 누릅니다.

> 김민수 소비자 화면입니다. 진행중인 파워짐 피트니스, 완료된 강남 블루보틀, 환불/취소 상태의 헤어살롱 루나를 한 번에 볼 수 있습니다. 화면은 원화가 우선이고, RLUSD는 XRPL 보호 원장 증빙용 보조 단위로 표시됩니다.

파워짐 피트니스 상세를 엽니다.

> 6개월 결제 중 이미 이용한 월은 released, 아직 이용하지 않은 월은 pending으로 남습니다. XRPL 증빙 카드에서는 tx hash와 Testnet explorer 링크를 확인할 수 있습니다.

## 3. 사업자 QR 생성

프로필에서 로그아웃한 뒤 Business `010-1000-0002`로 로그인합니다. `새 보호 결제 만들기` 또는 하단 `결제` 탭을 엽니다. 금액 `810000`, 기간 `6`개월을 입력하고 QR을 생성합니다.

> 사업자는 결제 내용을 먼저 만들고 QR을 손님에게 보여줍니다. QR 생성 자체는 돈이 들지 않습니다. QR은 결제 요청 딥링크를 인코딩한 이미지이고, 실제 XRPL 비용은 에스크로 생성/정산/환불 트랜잭션을 제출할 때만 발생합니다.

생성된 QR과 `TP-...` 코드를 보여줍니다.

> 이 QR은 `trustpay://payment-request?code=...` 형태의 실제 결제 요청 payload를 담습니다. 데모에서는 손님 앱에 코드를 입력해 같은 흐름을 재현합니다.

## 4. 소비자 QR 승인

사업자에서 로그아웃하고 Consumer `010-2000-0001`로 다시 로그인합니다. `QR 스캔 결제`를 열고 방금 생성된 `TP-...` 코드를 입력합니다.

> 소비자는 카카오페이처럼 앱에서 계좌 승인을 합니다. 결제 금액은 원화로 확인하고, 보호 원장에서는 RLUSD 기준으로 월별 에스크로가 생성됩니다.

`계좌 승인 결제 요청`을 누르고 PIN `123456`을 입력합니다.

> 승인 후 새 보호 결제가 홈에 반영됩니다. 이미 이용한 월은 사업자에게 정산되고, 아직 이용하지 않은 월은 pending 상태로 보호됩니다.

## 5. 환불 보호와 XRPL 요약

기존 환불/취소 카드 또는 환불 검토 상태를 보여줍니다.

> 만약 사업자가 서비스를 중단하면 이미 이용한 금액은 유지하고, 미이용 pending 금액만 환불 대상으로 분리합니다. TrustPay의 핵심 XRPL 사용 지점은 RLUSD, Trust Line, XLS-85 Token EscrowCreate, EscrowFinish, EscrowCancel입니다. Demo Mode는 UX 안정성을 위한 시연이고, 실제 Testnet 검증은 문서와 스크립트로 분리해 제공합니다.

## 2. 프로젝트 소개

### 한 줄 정의 (Elevator Pitch)

TrustPay는 헬스장, 학원, 미용실 등 선불 결제 이용자를 위해 사업자 폐업 또는 서비스 중단 시 미이용분 환불이 어려운 문제를 RLUSD 기반 월별 XRPL Token Escrow로 해결하는 선불금 보호 핀테크 서비스입니다.

### 핵심 가치 제안 / 차별화 포인트

TrustPay는 선불금을 결제 즉시 사업자에게 전액 지급하지 않고, RLUSD를 월별 단위로 XRPL XLS-85 Token Escrow에 분할 예치합니다. 기존 선불 결제에서는 6개월 이용권 결제 시 100% 금액이 즉시 사업자에게 이전되어 폐업 시 소비자가 잔여 이용분을 회수하기 어렵습니다. TrustPay에서는 예를 들어 600 RLUSD, 6개월 이용권을 100 RLUSD씩 6개의 월별 에스크로로 나누고, 사업자는 서비스를 제공한 월에 대해서만 EscrowFinish로 정산받습니다. 아직 이용하지 않은 월차는 pending 상태로 남아 EscrowCancel 기반 환불 흐름의 근거가 됩니다.

기존 소비자보호원 중재나 민사 소송은 피해 발생 이후의 사후 구제이고, 장기 선불 결제에 대한 실시간 자금 상태 증빙을 제공하지 못합니다. TrustPay는 결제 시점부터 정산 가능 금액과 보호 중인 미이용 금액을 분리하고, 사용자는 앱에서 released, pending, refunded 상태와 거래 증거를 확인할 수 있습니다. XRPL은 평균 수 초 단위의 빠른 합의와 매우 낮은 네트워크 수수료를 제공하며, Trust Line과 Token Escrow 기능을 통해 별도 스마트컨트랙트 없이 issued currency 기반 선불금 잠금/정산/환불 흐름을 구현할 수 있습니다.

### 주요 기능

1. 월별 Token Escrow 생성 — 소비자가 총액과 이용 개월 수를 입력하면 선불금이 RLUSD 월별 에스크로로 분할 예치됩니다.
2. 소비자 에스크로 대시보드 — 소비자는 진행중, 완료, 환불된 에스크로와 월별 released/pending/refunded 상태를 확인합니다.
3. 사업자 월별 정산 — 사업자는 서비스 제공 월이 도래한 금액만 EscrowFinish 흐름으로 정산받습니다.
4. 미이용분 환불 보호 — 서비스 중단 또는 폐업 시 pending 월차를 EscrowCancel 환불 대상으로 분리해 소비자 보호 흐름을 시연합니다.
5. Demo/Testnet 검증 분리 — Demo Mode는 3분 내 제품 UX를 안정적으로 시연하고, Testnet 스크립트는 XRPL Trust Line, EscrowCreate, EscrowFinish, EscrowCancel 트랜잭션 근거를 확인합니다.

### 타깃 사용자/시장

1차 타깃은 헬스장, 필라테스, 학원, 미용실, 네일샵 등 장기 선불 결제가 빈번한 업종의 국내 소비자와 소규모 사업자입니다. 소비자는 사업자 폐업 또는 서비스 중단 시 미이용분을 돌려받기 어려운 불안을 갖고 있고, 사업자는 소비자 불신 때문에 장기 이용권 판매와 선결제 전환에 어려움을 겪습니다.

확장 타깃은 프랜차이즈 본사, 지역 기반 생활서비스 플랫폼, 선불권 결제를 운영하는 SaaS/POS 사업자입니다. 이들은 TrustPay의 선불금 보호 인증, 월별 정산 대시보드, 환불 증빙 구조를 기존 결제/회원권 시스템에 붙여 소비자 신뢰를 높일 수 있습니다.

### 비즈니스 모델

MVP 단계에서는 수익 모델을 적용하지 않고, 데모와 Testnet 검증을 통해 제품 가능성을 검증합니다. 상용화 단계에서는 두 가지 수익원을 계획합니다.

1. 에스크로 생성 수수료: 사업자 또는 플랫폼 파트너에게 거래액의 0.5~1.0% 부과
2. 사업자 구독료: 선불금 보호 인증 배지, 정산/환불 대시보드, 리포트 제공 대가로 사업자당 월 5만 원 수준 부과

1차 파일럿 가정은 사업자 50곳, 사업자당 월 신규 선불 계약 20건, 평균 선불 결제액 30만 원입니다. 이 경우 월 보호 결제 규모는 약 3억 원이며, 0.5% 거래 수수료 기준 월 150만 원, 사업자 구독료 월 250만 원으로 월 매출 약 400만 원을 예상할 수 있습니다. 이후 500개 사업자로 확장하면 동일 가정 기준 월 보호 결제 규모 약 30억 원, 월 매출 약 4,000만 원 수준까지 확장 가능합니다.

## 3. 해결하고자 하는 문제

### 문제 정의 (현황·Pain Point)

국내 헬스장, 학원, 미용실 등 생활서비스 업종에서는 장기 이용권을 할인된 가격에 판매하는 선불 결제가 흔합니다. 소비자는 3개월, 6개월, 12개월 이용료를 먼저 결제하지만, 결제 이후 사업자가 폐업하거나 서비스를 중단하면 남은 이용분을 돌려받기 어렵습니다. 실제 상황에서는 사업자가 연락을 끊거나 환불 재원이 남아 있지 않은 경우가 많고, 소비자는 소비자보호원 상담, 분쟁 조정, 민사 절차에 의존해야 합니다. 이 과정은 시간이 오래 걸리고 소액 피해에는 실효성이 낮아, 소비자는 장기 선불 결제를 기피하고 성실한 사업자도 신뢰를 증명하기 어렵습니다.

### 문제의 규모/심각성

공정거래위원회와 한국소비자원 자료를 바탕으로 한 국회 정무위원회 공개 자료에 따르면, 2020년부터 2025년 8월까지 한국소비자원에 접수된 폐업 관련 선불거래 피해구제 신청은 총 987건, 피해 금액은 약 2억 1,295만 원으로 보도되었습니다. 이는 공식 피해구제 신청으로 집계된 수치이며, 실제 피해는 소비자가 신고를 포기하거나 소액 피해로 처리하지 않는 경우까지 고려하면 더 클 수 있습니다. 특히 헬스장, 필라테스, 학원, 미용실과 같은 업종은 장기 선결제와 폐업 리스크가 동시에 존재해 반복적인 소비자 피해가 발생합니다.

데이터 출처: 공정거래위원회·한국소비자원 제출자료 기반 국회 정무위원회 공개/언론 보도(2025년 10월 보도 기준), 한국소비자원 및 1372 소비자상담센터 선불 서비스 관련 상담 사례.

### 기존 솔루션의 한계

기존 해결 방식은 대부분 사후 구제에 가깝습니다. 소비자보호원 상담이나 분쟁조정은 이미 피해가 발생한 뒤 진행되며, 사업자가 폐업했거나 환불 재원이 없으면 회수가 어렵습니다. 민사 소송은 시간과 비용이 많이 들어 소액 선불 피해에는 현실적인 선택지가 되기 어렵습니다. 신용카드 할부항변권은 일부 고액·장기 할부 결제에서 방어 수단이 될 수 있지만, 계좌이체, 일시불 결제, 플랫폼 외 결제에는 적용 범위가 제한적입니다. 또한 기존 결제 시스템은 소비자가 결제 후 잔여 선불금이 실제로 어디에 보관되어 있는지 실시간으로 확인할 수 있는 투명한 증빙을 제공하지 못합니다.

### 본 프로젝트의 접근 차별성

TrustPay는 선불금 보호를 피해 발생 이후가 아니라 결제 시점부터 설계합니다. 소비자가 결제한 금액은 사업자에게 전액 이전되지 않고, 월별 RLUSD Token Escrow로 나뉘어 XRPL에 잠깁니다. 사업자는 실제 서비스를 제공한 월차만 EscrowFinish로 정산받고, 아직 이용하지 않은 월차는 pending 상태로 남습니다. 서비스 중단 또는 폐업 시에는 이미 이용한 released 금액과 미이용 pending 금액이 분리되어 있으므로, 미이용분만 환불 대상으로 처리하는 흐름을 명확히 만들 수 있습니다. 즉, TrustPay는 선불금의 소유·정산·환불 상태를 월 단위로 분리해 소비자 보호와 사업자 정산 신뢰를 동시에 제공합니다.

### XRPL을 선택한 이유

XRPL은 TrustPay의 목적에 맞는 원장 기능을 프로토콜 레벨에서 제공합니다. 첫째, XLS-85 Token Escrow를 통해 XRP뿐 아니라 RLUSD와 같은 issued currency를 시간 조건 기반으로 잠글 수 있어, 선불금 월별 예치에 적합합니다. 둘째, Trust Line 기능을 통해 소비자와 사업자 지갑이 RLUSD를 안전하게 주고받도록 설정할 수 있습니다. 셋째, 평균 수 초 단위의 빠른 합의와 낮은 트랜잭션 수수료는 월별 소액 정산과 환불에 적합합니다. 넷째, 별도 스마트컨트랙트 배포 없이 XRPL의 EscrowCreate, EscrowFinish, EscrowCancel primitive를 사용하므로 MVP 단계에서 구현 복잡성과 스마트컨트랙트 보안 리스크를 줄일 수 있습니다. 전통 DB만으로도 화면 상태는 만들 수 있지만, 자금 잠금과 정산 조건의 외부 검증 가능성은 제공하기 어렵기 때문에 XRPL을 핵심 인프라로 선택했습니다.


진행 현황:

TrustPay는 현재 MVP를 보유한 상태입니다. NestJS API, Prisma/SQLite 데이터베이스, React Native Expo 모바일 앱, xrpl.js 기반 XRPL 클라이언트가 구현되어 있으며, Demo Mode에서 소비자 계좌 승인 보호 결제부터 사업자 정산과 환불 보호까지 전체 흐름을 시연할 수 있습니다. API E2E 테스트, 모바일 테스트, XRPL Testnet 검증 스크립트, 제출용 README와 데모 문서도 준비되어 있습니다. 상용화 전에는 비커스토디얼 또는 HSM/MPC 기반 지갑 구조, 오픈뱅킹/계좌 결제 PG 연동, 사업자 신원 검증, 실제 결제/정산 운영 정책, 법적 환불 프로세스 연동을 추가로 검토할 예정입니다.
